# Статические токены машинных учетных записей

Человек входит через OAuth (нажать «Разрешить» в браузере). Машине, агенту без браузера, нажать некому, а давать ей токен человека нельзя: журнал перестает отвечать на вопрос «кто это сделал», и границы пришлось бы ставить на всех сразу. Решение: предвыданный токен машинной учетки с собственной политикой.

Код: `vault_mcp/static_tokens.py` (разбор файла хешей, без импорта fastmcp, тестируется офлайн) и обвязка в `vault_mcp/server.py`.

## Как это работает

- OAuth-провайдер работает как раньше: все OAuth-маршруты и discovery-документы остаются на нем.
- Если задан `MCP_STATIC_TOKENS_FILE`, проверка bearer-токена расширяется: сначала пробует провайдер, затем наш верификатор.
- Верификатор отвечает только на токены с префиксом `ovm_`, чтобы протухшие JWT коннектора не засоряли журнал отказов.
- Авторизация решает строка в файле хешей: она и есть allow-list машинной учетки. OAuth-вход по-прежнему проверяется по `MCP_ALLOWED_USERS`, и пустой список не пускает никого.
- Файл перечитывается при изменении (по mtime и размеру): выдать, отозвать или поменять политику можно без перезапуска сервера.
- В файле только ХЕШИ токенов (sha256). Сам токен существует в одном месте: у того, кому выдан.

## Формат файла

`MCP_STATIC_TOKENS_FILE`, одна учетка на строку:

```
# login  algo    hash(hex)                                                         expires     policy
agent    sha256  9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08  2027-03-01  deny=delete_note,delete_section
reader   sha256  1f2c…                                                             2027-06-01  readonly
```

- поля через пробел; `#` (комментарий) и пустые строки игнорируются;
- `hash` это sha256 сырого токена в hex. Медленный хеш не нужен: токен это 32 случайных байта, перебор невозможен при любой скорости хеша;
- `expires` это ПЕРВЫЙ день (UTC), когда токен уже НЕ действует;
- `policy` необязательна: `readonly` (отказ на каждый пишущий инструмент) или `deny=<инструмент>[,…]` из списка: `create_note`, `write_note`, `append_to_note`, `patch_note`, `edit_frontmatter`, `delete_section`, `delete_note`, `rename_note`;
- битая строка (не тот алгоритм, не-hex, плохая дата, опечатка в политике) отбрасывается сама и пишется в лог с номером строки, остальные работают. Опечатка закрывает учетку, а не открывает ей больше, чем задумано.

Монтируйте в контейнер КАТАЛОГ с файлом и только на чтение (так сделано в `docker-compose.yml`). Bind-mount одного файла держит inode: `sed -i` и редакторы пишут новый файл и переименовывают, контейнер продолжал бы видеть старое содержимое.

## Выдача токена

```bash
python tools/issue_token.py --login agent --expires 2027-03-01 \
    --deny delete_note,delete_section --keychain vault-mcp
# stdout: agent sha256 <64 hex> 2027-03-01 deny=delete_note,delete_section
```

Токен НЕ печатается: он уходит в файл 0600 (`--out`, существующий файл не перезаписывается) или в Keychain macOS (`--keychain`); в stdout только строка для файла хешей. Передавать токен аргументом нельзя на уровне интерфейса: аргументы попадают в историю оболочки и транскрипты. Для уже существующего токена: `--hash-only --from-file <path>` (например, чтобы сменить политику).

Строку дописать в файл на сервере; со следующего запроса токен работает. Смена токена это замена строки, отзыв это удаление строки, смена политики это правка пятого поля. Перезапускать ничего не нужно.

## Отказы и журнал

Нет токена, неизвестный, отозванный, просроченный: стандартный 401. Причина в теле не передается, она в журнале `${MCP_LOG_DIR}/mcp-auth.jsonl`: по строке на отклоненный `ovm_`-токен (`reason: unknown | expired`, отпечаток токена, логин для просрочки). Отзыв и «никогда не выдавался» неотличимы: обе записи `unknown`.

Отказ по политике это ответ инструмента (HTTP 200), а не транспортная ошибка:

```
ERROR: tool 'delete_note' is denied for user 'agent'
ERROR: server is read-only for user 'reader'
```

Отказ тоже попадает в `mcp-writes.jsonl` с `ok: false`.

## Приемка

Пробник (только stdlib) проходит весь сценарий: вход, создание заметки, правка, отказы по политике, чтение:

```bash
VAULT_MCP_TOKEN=$(cat /path/to/token-file) \
    VAULT_MCP_URL=https://your-domain/mcp \
    python tools/probe_static_token.py
```

## Рекомендации

- Одна строка = один токен. Второму контейнеру нужна своя учетка (`agent-dev`), а не общий токен.
- Рабочая рекомендация для агента: `deny=delete_note,delete_section`. Агент читает и правит (иначе он бесполезен), но удалять не может: удаление это решение человека.
- Границы проводятся по ИНСТРУМЕНТАМ, а не по папкам: перечень «куда агенту можно писать» не составить заранее, перечень «что нельзя» это два имени.
- Токен показывать нельзя нигде: ни в логах, ни в транскриптах, ни в git. Показанный один раз секрет считается скомпрометированным, лечится только выдачей нового.
- Не хранить токен в `.mcp.json` открытым текстом: файл 0600 плюс переменная окружения (`"Bearer ${VAULT_MCP_TOKEN}"`).
